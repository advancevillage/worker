# Go 服务开发规范

先确认项目 Go 版本、现有架构与检查命令；按任务读取下方资料。必须项用于保证正确性，默认项允许按项目约定调整，条件项仅在相应需求出现时采用。

## 工作区默认约定

用户明确要求优先；本工作区默认采用接口暴露业务能力、Option 接口配置对象、`pkg/const.go` 集中定义常量。Google/Uber 补充编码与正确性规范；已有项目按当前任务范围保持兼容。具体规则按下方专题读取。

## 核心规则

- 默认保持简单：接口按职责拆分，配置采用 Option；泛型和其他模式按实际需求使用。
- 必须保持边界清晰：依赖无环，业务规则归所属领域，依赖显式组装。
- 必须处理错误：保留必要上下文，在责任边界处理与记录，避免逐层重复日志。
- 必须控制并发：传递取消信号，限制并发量，保护共享状态，等待后台任务退出。
- 必须明确数据与资源责任：约定所有权、关闭与事务边界；重试前确认幂等性和期限。
- 必须验证相关行为：格式化、适用测试与静态检查；并发改动检查竞态，性能优化先测量。

## 按需读取

- 系统选型、跨模块边界调整或架构重构：[架构设计](../architecture-design-skills/SKILL.md)，普通局部编码无需读取。

## 验证与交付

执行 `gofmt`、相关 `go test` 和 `go vet`；沿用项目的 lint 配置。并发改动执行相关 `go test -race`，记录未能完成的检查及原因。测试覆盖行为与失败边界，避免复刻实现；交付说明变化、验证和剩余限制。
