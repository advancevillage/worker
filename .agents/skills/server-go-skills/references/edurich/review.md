# EduRich 评估与待决事项

所有验证状态目前均为“未做真实双端验证”。概念图仅展示目标视觉；不能据此确认字体、基线、公式命令和断行兼容。

## 四项质量目标

| 目标 | 验证方式 | 记录内容 |
| --- | --- | --- |
| 易用性 | 同一道真实教材题分别由人工与 AI 编写、修改 | 用时、错误率、字段冗余、诊断修复难度 |
| 可用性 | Flutter/Web 消费相同样例，在窄屏、大字号、离线下检查 | 内容完整性、阅读顺序、基线、溢出和资源降级 |
| 可扩展性 | 模拟新增模块、旧端读取和必需/可选协商 | 是否需改 core、未知节点是否丢失语义 |
| 可维护性 | 模拟版本迁移与渲染器替换 | 差异、ID 稳定性、迁移诊断和维护重复度 |

不预设通过率或视觉容差；真实实验前先定义可复现环境、验收阈值及样例版权来源。

## 首批验收场景

1. 中文标点、中英文、空格、单位、行内分数与根号混排。
2. 公式内中文、上下标、错误命令和超长不可拆公式。
3. 宽屏双列与窄屏纵排，字号放大且无裁切。
4. 图片比例、离线加载、缺失资源、alt 和图注阅读顺序。
5. 重复 ID、悬空引用、未知字段、未知模块与 fallback。
6. 深层嵌套、大图和复杂公式超限，诊断具有路径。
7. 旧版内容显式迁移，原文不被渲染阶段改写。
8. 候选模块先用真实样例说明表达缺口，再升级标准。

## 优先讨论的不足

| 待决项 | 需要决定的问题 |
| --- | --- |
| 数学能力交集 | 命令、字体、竖式、方程组、矩阵、化学式如何分级？ |
| 作者输入 | JSON 编辑成本是否可接受？是否需要 Markdown 子集及无损往返？ |
| 教材文字排版 | 中文禁则、拼音注音、着重号、下划线、强制换行如何表示？ |
| 布局 | 固定图宽、图文环绕、叠加与裁剪是否必须进入首版？ |
| 表格 | 合并单元格、单元格内公式、跨页表头与阅读顺序如何定义？ |
| 题目与交互 | 题号、选项、填空、拖拽、事件和答案保密边界如何分离？ |
| 分页与输出 | 响应式学习内容和固定教材复刻是否使用不同 profile？ |
| 资源封装 | 离线包、字体许可、摘要格式、失效资源和资源更新如何约定？ |
| 无障碍 | 公式朗读、屏幕阅读器顺序、语言切换与交互焦点如何表达？ |
| 内容溯源 | 来源页码、版权、修订记录是否作为独立可选元信息？ |
| 兼容维护 | 模块版本矩阵、能力档案和弃用周期由谁维护？ |

建议先决定目标是“自适应教学内容”还是“原教材页面精确复刻”；当前草案选择前者作为探索起点，后者需要独立分页及字体度量规范。

## 冻结条件

核心字段和每种节点均有完整约束、正反例及诊断；资源与数学能力清单明确；同批真实教材样例经过 Flutter/Web 验证；未通过项转为可协商能力或明确排除。正式 JSON Schema、解析器、渲染器与自动化测试留给后续实施，本次不生成。
