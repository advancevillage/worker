# 架构决策与验证

## 选型依据

图书第 18 章预览强调：风格选择依赖架构特性、领域、战略目标与组织情境。第 19 章预览强调：收集信息、说明理由、记录并传达决定。工作区据此比较关键目标的满足程度、复杂度、团队能力、成本与迁移代价，不按流行程度或单一总分选型。

## 决策与图示

影响边界、数据、部署、核心质量或长期成本的选择记录 ADR；局部调整保留必要说明即可。紧凑 ADR 包含：状态、上下文与约束、候选、决定与理由、收益和代价、验证证据、复评条件。后续决定通过替代关系演进，保留历史。

按需使用以下工作区最小模板，新增字段围绕具体决策：

| 字段 | 写什么 |
|---|---|
| 标题与状态 | 一个重大选择；提议、接受、废弃或被替代；替代时链接后续 ADR |
| 上下文 | 业务驱动、现状、关键质量目标与约束 |
| 候选与决定 | 可行候选、推荐及理由，已接受的决定与提议分清 |
| 后果 | 收益、负面代价及对实现、运维和团队的影响 |
| 验证与复评 | 证据、尚未验证的假设、目标或约束变化后的复评条件 |

自编示例：订单和库存必须在现有本地事务内保持不变量，当前团队缺乏分布式发布能力，因此先用模块化单体；接受共享发布代价，出现明确独立扩容收益后复评。该示例不预设所有订单系统都应采用同一方案。

图示按问题选择上下文、容器、组件、序列或部署视图，不强制所有图层。箭头标明源码依赖或运行时交互、同步/异步及必要协议；标明数据与部署边界，统一图例。C4 容器是应用或数据存储单元，不等于 Docker。沿用项目支持的格式，简单图可用 Mermaid。

图书预览要求表现一致：展示局部前说明它在整体中的位置。本地工作区用图规则：上下文图说明用户和外部系统；容器图说明应用、数据存储及其通信；组件图展开一个应用内部的职责；序列图解释关键交互和失败；部署图说明节点、副本与环境。容器图不承担所有物理部署细节，图中局部名称应与整体一致。

## 风险与演进

- 关键风险写出可能性、影响、证据和验证或缓解方式；优先验证可能推翻选型的假设，未验证结果明确标出。
- 图书风险预览以影响和发生可能性两个维度评估风险。工作区记录风险场景、这两个维度、证据、缓解责任与验证；评分只是排序辅助，不能把估计当作概率或已验证结论。多人评估时先分别识别，再讨论分歧与缓解方案。
- 将关键特性转为适应度函数（fitness function）或适用检查，例如模块依赖检查、契约兼容检查、负载测量和恢复验证；检查阈值依据业务目标与基线，不为文档形式引入工具。
- 图书第一章公开节选及补充资料将适应度函数用于对重要架构特性提供客观的反馈。工作区将它落实为可重复的约束或组合效果检查，不等同业务功能测试。自编示例：检查领域代码是否导入 UI/数据库实现；在约定负载下检查尾延迟；故障演练检查恢复与核对目标。说明条件、基线、阈值、执行时机与失败处理，适用时自动执行。
- 演进说明触发条件、迁移步骤、兼容策略、数据迁移与失败恢复；拆服务前确认边界和收益，避免用架构更新触发未经任务授权的全面重构。

交付按任务规模包含约束、质量目标、候选取舍、关键边界、决策及验证；沿用项目文档位置。新项目按工作区约定生成本地计划，长期维护的 ADR 与图示随项目仓库管理。

## 场景自检

| 场景 | 检查重点 |
|---|---|
| 小系统或局部功能 | 满足目标的简单方案；不强制微服务、完整图层或 ADR |
| 插件扩展 | 稳定核心、契约版本、插件依赖与故障隔离 |
| 异步消息 | 一致性、可靠交付、重复、失败与重放责任 |
| 服务拆分 | 数据所有权、独立发布收益、运维成本及迁移恢复 |
