# 软件架构设计规范

先确认业务约束、现有架构和任务范围；用户指定的方案与项目约定优先。按规模裁剪以下流程，局部修改无需完整选型。

默认使用下方本地资料，核心概念与操作规则无需访问外链。外链仅作来源追溯；核实新版本或资料未覆盖的具体问题时再联网。资料中的图书归纳、补充来源和工作区建议分别标明。

## 核心流程

- 明确业务驱动与关键质量目标，写出优先级、作用范围和验证方法；未知指标标为待确认，不编造容量或承诺。
- 比较满足约束的候选，说明推荐理由和接受的代价；默认从简单方案评估，拆服务需有独立发布、扩容或责任隔离收益。
- 明确组件职责、依赖方向、通信契约、数据所有权与部署边界；目录划分不等于部署隔离。
- 重大选择记录 ADR，关键风险有验证或缓解方式；按需画图并说明演进触发条件。

## 按需读取

- 架构选型、风格比较：[架构风格](references/architecture-styles.md)。
- 质量目标、组件与数据边界：[设计原则](references/design-principles.md)。
- 决策记录、架构图、风险与演进：[决策与验证](references/decisions-and-validation.md)。

## 交付

方案说明主要约束、选择及代价、关键边界和验证结果；评审指出问题、影响与可执行调整。沿用项目文档格式，仅计划任务交付计划；未验证事项明确标出。语言、平台及事务、幂等、重试等实现规则继续遵守对应专题。
